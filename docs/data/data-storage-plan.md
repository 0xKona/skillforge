# Data Storage Plan

This document outlines the strategy for storing and managing data within the SkillForge application. The core data entities are **CVs**, **Ingots**, and **Billets**.

## 1. Data Entities Overview

### 1.1. CV (Curriculum Vitae)

The central document generated by the user.

- **Purpose**: Represents a tailored collection of skills and experiences.
- **Structure**:
    - **Metadata**: Title, creation date, last modified, target job/role.
    - **Sections**: Ordered list of sections (e.g., "Education", "Work Experience").
    - **Content**: References to specific **Ingots** included in each section.

### 1.2. Ingot

A modular entry representing a specific block of information.

- **Purpose**: To store reusable pieces of information that can be added to multiple CVs.
- **Examples**: A specific job role, a degree, a certification, a hobby.
- **Structure**:
    - **Type**: The category of the ingot (e.g., `ingot_education`, `ingot_experience`).
    - **Fields**: Key-value pairs specific to the type (e.g., `schoolName`, `startDate`).
    - **Billets**: An embedded list of sub-entries (e.g., modules, projects) stored directly within the Ingot.

### 1.3. Billet (Embedded)

A granular sub-entry nested within an Ingot.

- **Purpose**: To provide detailed breakdowns within an Ingot.
- **Storage**: Stored as a JSON array within the parent Ingot's `billets` field.
- **Structure**:
    - **Type**: The category of the billet (e.g., `billet_edu_module`).
    - **Fields**: Key-value pairs specific to the type.

## 2. Amplify Data Schema (Gen 2)

We will use AWS Amplify Data (backed by AppSync and DynamoDB) to store these entities.

### 2.1. Proposed Schema (`amplify/data/resource.ts`)

```typescript
import { type ClientSchema, a, defineData } from '@aws-amplify/backend';

const schema = a.schema({
    // The CV Entity
    CV: a.model({
        // ... (same as before)
    }),

    // The Ingot Entity
    Ingot: a
        .model({
            name: a.string().required(),
            type: a.string().required(),

            // Stores the dynamic fields (schoolName, dates, etc.)
            content: a.json(),

            // Stores the embedded billets list
            billets: a.json(),
        })
        .authorization((allow) => [allow.owner()]),
});
```

### 2.2. Rationale

- **Embedded Billets**: Billets are strictly owned by an Ingot and rarely accessed independently. Embedding them reduces database calls (N+1 problem) and ensures atomic updates.
- **JSON Fields**: Provides flexibility for different template structures.

## 3. Service Classes Plan

### 3.1. `CvService`

(Unchanged)

### 3.2. `IngotService`

**File**: `src/lib/classes/ingot-service.ts`

- **Responsibilities**: Manage Ingot creation and updates, including their embedded billets.
- **Methods**:
    - `createIngot(type: string, name: string, content: any, billets: any[]): Promise<Ingot>`
    - `getIngot(id: string): Promise<Ingot>`
    - `listIngots(type?: string): Promise<Ingot[]>`
    - `updateIngot(id: string, content: any, billets: any[]): Promise<Ingot>`
    - `deleteIngot(id: string): Promise<void>`

### 3.3. `BilletService`

(Removed - logic moved to IngotService/Frontend)

## 4. Implementation Steps

1.  **Update Backend**: Modify `amplify/data/resource.ts` with the proposed schema and deploy.
2.  **Generate Client**: Ensure the frontend client is generated (`npx ampx generate outputs`).
3.  **Create Types**: Define TypeScript interfaces for the JSON content structures (based on `_ds_templates`) to ensure type safety within the Service classes.
4.  **Implement Services**: Create the class files in `src/lib/classes/`.
5.  **Integrate**: Use these services in the `Forge` (Ingot management) and `Anvil` (CV building) pages.
