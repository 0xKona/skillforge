# Deployment

## Overview

SkillForge uses a three-stage deployment model:

| Stage | Purpose | How it's deployed |
|-------|---------|-------------------|
| **dev** | Local development sandbox | Manual: `bun run infra:dev` |
| **test** | Pre-prod validation | Automatic: pipeline deploys on push to `main` |
| **prod** | Production | Pipeline: after manual approval in AWS Console |

## Pipeline Flow

```
Push to main
  |
  v
[Source] GitHub via CodeStar connection
  |
  v
[Build] Install deps, compile Go Lambdas, CDK synth
  |
  v
[Deploy Test] Backend (Cognito, DynamoDB, S3, API Gateway, Lambda)
              + Frontend (Amplify Hosting triggers build)
  |
  v
[Manual Approval] Review in AWS Console
  |
  v
[Deploy Prod] Same as test, with CMK encryption + deletion protection
```

## Local Development

```bash
# Deploy dev backend + generate frontend env vars
bun run infra:dev

# Start frontend against dev backend
bun run dev
```

## Commands Reference

| Command | Action |
|---------|--------|
| `bun run infra:dev` | Deploy dev backend + generate `frontend/.env.local` |
| `bun run infra:synth` | Synthesise CloudFormation templates (no deploy) |
| `bun run infra:diff` | Show pending changes vs deployed |
| `bun run infra:deploy:test` | Deploy test stack directly (bypasses pipeline) |
| `bun run infra:deploy:prod` | Deploy prod stack directly (requires approval) |
| `bun run infra:deploy:pipeline` | Deploy/update the pipeline itself |
| `bun run infra:config:test` | Generate `frontend/.env.local` from test outputs |
| `bun run infra:config:prod` | Generate `frontend/.env.production.local` from prod outputs |

## First-Time Setup

1. **Bootstrap CDK** (once per account/region):
   ```bash
   cd infra && npx cdk bootstrap aws://ACCOUNT_ID/eu-west-2
   ```

2. **Create CodeStar GitHub connection** (AWS Console > Developer Tools > Connections). Note the ARN.

3. **Store GitHub token** in Secrets Manager as `skillforge/github-token`.

4. **Deploy the pipeline**:
   ```bash
   bun run infra:deploy:pipeline -c connectionArn="arn:aws:codestar-connections:..."
   ```

5. Push to `main` -- the pipeline runs automatically from here on.

## Environment Variables

The frontend requires these `NEXT_PUBLIC_*` vars (auto-generated by `infra:config:*`):

- `NEXT_PUBLIC_API_URL` -- API Gateway endpoint
- `NEXT_PUBLIC_USER_POOL_ID` -- Cognito User Pool ID
- `NEXT_PUBLIC_USER_POOL_CLIENT_ID` -- Cognito App Client ID
- `NEXT_PUBLIC_IDENTITY_POOL_ID` -- Cognito Identity Pool ID
- `NEXT_PUBLIC_S3_BUCKET` -- Avatar storage bucket name
- `NEXT_PUBLIC_AWS_REGION` -- AWS region

In the pipeline, these are injected into Amplify Hosting automatically from CDK stack outputs.

## Prod Protections

- DynamoDB tables: `RemovalPolicy.RETAIN` + Point-in-Time Recovery
- S3 bucket: `RemovalPolicy.RETAIN`
- Cognito User Pool: deletion protection enabled
- DynamoDB + S3 encrypted with Customer Managed KMS Key (audit via CloudTrail)
- Pipeline requires manual approval before prod deployment
